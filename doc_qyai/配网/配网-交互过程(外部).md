
基于BLE(蓝牙低功耗)实现配网。

## 一、配网原理

1. **BLE通信基础**：
- 设备作为BLE Peripheral(外围设备)广播自身存在
- 手机作为BLE Central(中心设备)扫描并连接
- 通过GATT服务进行数据交换

2. **配网数据格式**：
- 使用自定义协议格式，可以有特定的头部格式，比如以"JL"开头
- 使用CRC16校验数据完整性(设备端有做校验)

## 二、配网流程

1. **设备广播阶段**：
- 设备初始化BLE并开始广播(ADV_IND)，轻语AI方案中设置了提示音“进入配网模式..."。
- 广播包中包含设备名称和MAC地址
- 广播间隔设置为160ms(ADV_INTERVAL_MIN)

2. **手机连接阶段**：
- 手机扫描并发现设备
- 发起BLE连接请求
- 连接成功后进行MTU协商

3. **配网数据传输**：
- 手机向设备写入配网数据(SSID和密码)，格式见下文。
- 手机端的数据写入到特征值ATT_CHARACTERISTIC_ae81_01_VALUE_HANDLE
- 设备接收并校验数据完整性

4. **配网处理阶段**：
- 设备解析收到的配网数据
- 设备端设置网络参数
- 设备端返回配网状态给手机(成功/失败等)

5. **结果反馈阶段**：
- 设备通过写入特征值ATT_CHARACTERISTIC_ae82_01_VALUE_HANDLE发送响应数据到手机端
- 响应状态码定义如下：
- 0: 配网成功
- 1: 正在配网
- 2: 配网失败
- 3: 未找到SSID
- 4: 密码错误

6. **附加信息反馈**：
- 配网成功后，设备会再次发送MAC地址、UUID等信息[比如4G模组的ICCID、wifi_mac地址等]，也是JSON格式的。

## 三、数据格式
手机端通过BLE向设备端下发WiFi名称(SSID)和密码的格式如下：
### 数据格式结构
1. **协议头**：固定以"JL"开头（0x4A, 0x4C）
2. **数据长度**：2字节（大端格式），表示后续数据的长度
3. **命令类型**：
- 一级命令：0x10（网络配置相关）
- 二级命令：0x01（表示WiFi配网）
4. **数据内容**：JSON格式的WiFi信息
5. **校验**：2字节CRC16校验（从命令类型开始到数据内容结束）
6. **结束符**：0xFF

### 示例JSON数据结构
```json
{
"ssid": "Your_WiFi_SSID",
"password": "Your_WiFi_Password"
}
```

### 完整数据包示例（十六进制）
```
4A 4C 00 1A 10 01
7B 22 73 73 69 64 22 3A 22 59 6F 75 72 5F 57 69
46 69 5F 53 53 49 44 22 2C 22 70 61 73 73 77 6F
72 64 22 3A 22 59 6F 75 72 5F 57 69 46 69 5F 50
61 73 73 77 6F 72 64 22 7D
XX XX FF
```
（其中XX XX为CRC16校验值）

### 注意事项
1. 数据总长度不应超过128字节（包括协议头、校验等）
2. CRC16校验范围是从命令类型(0x10)开始到JSON数据结束
3. 设备端收到后会返回配网状态（成功/失败等），见`rsp_cmd0`-`rsp_cmd4`的定义
